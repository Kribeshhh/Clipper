# Gaming Clipper

Read this file before making changes. Keep project context here and setup instructions in README.md.

## Purpose and MVP

Turn recorded gameplay and authorized YouTube Live or Twitch inputs into downloadable highlights. The confirmed MVP includes exciting and funny moment detection, subtitles, vertical output, preview, boundary adjustments and MP4 export.

## Current implementation

Phase 0 provides the deployment foundation and service-status view. Phase 1 adds the single-operator private studio, validated recorded MP4 uploads, a recording library, range-enabled previews, manual timestamp selection, durable render jobs, retry, progress, clip playback and download. Phase 2 adds on-demand recorded-video analysis, timestamped transcripts, ranked evidence-backed suggestions, bounded previews and editable clip selection. Phase 3 adds adjustable portrait reframing, burned-in subtitles, timed preview and approved batch exports. Phase 4 connects YouTube and Twitch channels, associates recordings, supports Twitch native clips and generates private highlights from an operator-supplied live encoder feed. Phase 5 hardens the personal installation and adds tested loopback HTTPS deployment and paired database/media recovery.

## Architecture and responsibilities

- React, TypeScript, Vite and Tailwind power frontend/src. The app manages the studio session and recording library. Components own the editor and health view. Services wrap HTTP and upload progress.
- FastAPI routes in backend/app/api authenticate media operations and validate requests. Core owns Pydantic settings, error responses, dependency checks and logging. SQLAlchemy models and Alembic migrations define videos, processing jobs and clips. Each clip points to its job, which stores its source and selected interval.
- Services validate and render media. FFprobe reads container and stream metadata. A bounded FFmpeg decode checks the stream before acceptance. Sources must be MP4 with one 8-bit H.264 video and optional AAC audio. Render output uses H.264/AAC with a shared seek interval and fast-start MP4.
- Private storage uses a local volume shared only by API and worker. The adapter maps typed UUIDs to paths. Writes use staged files and atomic rename. Hourly cleanup reclaims abandoned files older than a day.
- Celery Beat schedules a worker to claim queued jobs from PostgreSQL. Redis transports tasks. Session-level PostgreSQL advisory locks prevent concurrent renders and release on worker loss. A surviving job can be reclaimed up to three attempts before explicit retry. Repeated submission with the same request ID and interval returns the existing job.
- infrastructure/docker contains production images and the Nginx proxy. Scripts initialize secrets and the database role. Compose runs migrations first. The API and worker now require FFmpeg, FFprobe and Linux libseccomp. Phase 1 adds no Python or npm package dependencies.

## Recorded highlight analysis

- The editor submits an authenticated POST to /api/videos/{id}/analysis and polls GET on the same resource. PostgreSQL stores one analysis per immutable source with its weight snapshot, stage, progress, timestamps, intermediate observations and ranked results. Duplicate requests reuse the row. A weight change can rescore stored observations.
- The render worker's existing Beat scheduler dispatches analysis ticks to a separate Celery queue. A non-root, single-process analysis slot takes a PostgreSQL advisory lock, checkpoints completed stages, and reclaims interrupted work. The container has a 2 GiB memory limit, one CPU, read-only access to recordings and private temporary files. Prefork tasks have a 29-minute soft timeout and a 30-minute hard timeout.
- backend/app/services/analysis extracts mono 16 kHz PCM with the existing restricted FFmpeg runner. NumPy measures one-second RMS energy relative to the preceding six seconds. Local Faster-Whisper tiny uses CPU int8 inference with VAD on 30-second chunks, retaining bounded segment times and text. Speech activity and English reaction phrases supply separate cues. Silence and absent audio are valid. Speech inference failure produces an explicit warning and permits retry with cached visual observations.
- FFmpeg generates a 160 × 90, two-frame-per-second proxy. OpenCV reads samples sequentially, measuring grayscale histogram distance for cuts and mean absolute pixel change for activity. A strong cut is excluded from the motion measurement on that frame.
- Scoring uses one-second bins. A cue contributes when its normalized strength is at least 0.25 and its weight is positive. At least two cues and 18 points are required. Points equal 100 times the weighted sum of contributing strengths divided by the sum of configured weights. Higher points rank first, then earlier times. Each result records strengths, event time, available transcript evidence, audio level and visual measurements. Scores are deterministic ranking points.
- Suggestions include four seconds before and five seconds after the event, extending toward speech boundaries up to ten seconds on either side and clamping to the source. Keep at most 12 ranges, suppressing overlap, gaps under one second and repeated use of a speech segment. Empty results are valid. Preview and edit copies the range into the existing editor and uses the Phase 1 render endpoint.

## Vertical editing and subtitles

- The editor supports original-format export and 720 × 1280 portrait export. Highlight review opens portrait mode. The operator can adjust timing, crop position and captions, play the selection, approve up to 12 edits in a batch, and review each export independently.
- The authenticated edit-preview route intersects stored Faster-Whisper segments with the selection and returns clip-relative cues. No second inference pass is required. Long segments are paged into short lines with proportional timing inside the measured speech interval. Silent recordings and selections without speech produce clean exports. When transcription is unavailable, the editor offers analysis or explicit caption-free rendering.
- New analyses collect localized motion centroids from the existing low-resolution sample pass. A crop suggestion requires at least four observations, sufficient coverage of the interval, and 80% spatial agreement. The operator can apply it or use the center fallback. Older analyses use center framing. The detector measures movement and does not identify people, webcams or gameplay objectives.
- backend/app/services/editing separates interval validation, cue preparation, ASS writing, crop geometry, aspect conversion, FFmpeg arguments, encoding and FFprobe validation. One encode crops the displayed image, accounts for sample aspect ratio, fits square pixels to a 9:16 canvas and burns plain-text captions in outlined white type. The original soundtrack follows the same trim and is encoded as AAC. The original-format entry point also uses this renderer.
- Each job snapshots its settings and clip-relative cues. A batch inserts ordinary render jobs in one database transaction with stable per-selection request IDs. Existing rows migrate as original-format jobs. The worker verifies duration, audio presence, MP4/H.264 and portrait dimensions before atomic publication. It stores the measured stream metadata with the clip.
- FFmpeg needs libass and the production image includes DejaVu Sans. Native deployments must provide an FFmpeg build with the ass filter. The API accepts bounded numeric crop offsets, timing, and a caption flag. The worker constructs filters, writes a fixed caption filename in a private scratch directory, neutralizes ASS overrides and removes scratch files on exit. The orphan sweep covers abandoned work directories. Per-file limits, free-space checks and a transaction-locked aggregate export quota bound storage usage.

## Live providers and ingestion

- The existing private single-operator session owns both connections. The adapters in `backend/app/services/providers` implement separate Google and Twitch authorization-code grants. Redis holds expiring one-use state bound to the initiating session, provider and callback cookie. The API encrypts access and refresh tokens with Fernet (`cryptography`). Configure a stable API-only encryption key, registered callback origin and separate provider app credentials. Refresh and replace credentials under database locks. Disconnect removes local credentials and associations, closes feeds and attempts remote revocation.
- YouTube uses `youtube.readonly` to identify the operator’s channel and list up to 200 owned broadcasts with lifecycle status. Associate an independent authorized recording or start the operator’s encoder for a live broadcast. The YouTube integration retrieves metadata only. [Live broadcasts API](https://developers.google.com/youtube/data/live/reference/rest/v3/liveBroadcasts/list) · [YouTube API developer policies](https://developers.google.com/youtube/terms/developer-policies)
- Twitch validates channel identity, scopes and client ID, with startup and hourly credential checks. Helix retrieves stream status, lists channel clips, creates a clip on explicit operator request and polls for completion for up to 60 seconds. The owner grant uses `clips:edit` and `channel:manage:clips`. Clip import requires a URL returned by the official download endpoint on an allowed Twitch CDN host. Private studio exports are independent of native Twitch clip publication. [Twitch API reference](https://dev.twitch.tv/docs/api/reference/clips) · [Twitch token validation](https://dev.twitch.tv/docs/authentication/validate-tokens/)
- Only fixed provider API endpoints and validated HTTPS clip download URLs can be fetched. Redirects and environment proxies are disabled. The shared HTTP adapter bounds response sizes and timeouts, sanitizes errors and applies provider request budgets and quota cooldowns. Neither provider supplies a general stream capture URL.
- One active encoder feed receives ordered private MP4 segments through a feed-scoped, hashed bearer credential. The publisher reads local MPEG-TS from stdin, segments at forced keyframes and sends encoder presentation timestamps. Retries compare segment digests. Reconnect uses the server cursor and accounts for lost time. Compatible adjacent segments supply pre/post context. Timeline discontinuities and format changes delimit that context.
- `app/services/live/buffer.py` bounds media by time, bytes and segment count and applies backpressure before unprocessed footage can be evicted. Each segment goes through the recorded-media validator and the existing analysis queue. `app/workers/live.py` advances analyzed segments. `highlights.py` deduplicates ranges, remuxes context, shifts transcript timestamps and creates ordinary render jobs. The existing editor, preview, caption and download paths serve the saved highlights. Clean EOF, operator stop or idle expiry drains remaining work and releases rolling media.
- Segment inference can split utterances. Highlight availability depends on segment duration, post-event context and worker throughput. Long outages create real gaps. The default buffer is 120 seconds / 256 MiB with a 64-segment ceiling. Continuous input is limited to 24 hours per feed. Retained highlight windows and completed exports each have an aggregate storage budget. Native provider consent, quotas, disabled clipping and download entitlement depend on the registered channel and app.

## Security and coding standards

Use typed service boundaries, locked dependencies, structured errors and tests for failure paths. Keep secrets and internal paths out of client responses. Use generated identifiers and file storage outside web roots. Authenticate every media read and mutation. The studio uses one random operator key, constant-time comparison, expiring opaque sessions in Redis, HttpOnly SameSite cookies, Secure cookies in production, and a custom header for browser mutations. All sessions represent the same trusted operator.

Bound upload bytes while streaming and limit upload concurrency, input duration, frame size/rate, processing time, file sizes and encoder threads. Invoke media tools with argument arrays and a sanitized environment. Restrict demuxing to local MOV/MP4 with external references disabled. Linux child processes also use an address-space limit and seccomp syscall restrictions. Compose uses unprivileged containers, resource limits, internal database and broker ports, and loopback ingress. Provider adapters must respect the scope of each official media permission.

## Personal production security

- The existing generated operator credential remains the login method. Starlette’s authentication middleware establishes the single operator principal and the router guard requires its scope for all library, clip, job, provider and feed management operations. A bearer ingest credential is valid only for its one feed’s cursor, segment submission and EOF routes. There are no registrations or secondary principals. Each installation owns its database and media volume, including existing rows.
- Browser sessions have an eight-hour absolute lifetime, transport-secure HttpOnly cookies in production and hashed lookup handles. Session records are bound to the current operator credential with HMAC. New login invalidates the presented previous handle, logout deletes its Redis record, and operator-key rotation invalidates existing sessions and pending provider callbacks. The first Phase 5 deployment requires signing in again. Mutations check the studio header and any supplied Origin. One Redis bucket bounds login attempts independently of forwarded IP addresses.
- Routes use typed IDs, SQLAlchemy expressions and bound SQL parameters. The client cannot select an output path, demuxer, filter program, shell command or provider endpoint. The encoder publisher resolves the local FFmpeg executable. Output validation, temporary cleanup, fixed media subprocess limits and verified ownership stay on their normal entry points. React escapes text, plain-text subtitle preparation handles control syntax, and the proxy applies CSP and same-origin private media controls. Celery accepts JSON messages. Application and proxy access logs omit provider callbacks; runtime containers receive only their relevant service credentials.
- A locked publication check caps storage for uploads and Twitch imports. Segment admission loads source sizes and keys without reading transcripts or visual samples. A composite index supports the per-recording export history and another supports queued analysis lookup. The API pool has three persistent connections and up to two overflow slots with a two-second acquisition timeout. Render and analysis tasks use short-lived connections and session-scoped advisory locks.
- Compose has separate frontend/API and internal data networks, bounded logs and scratch space, restart policies and health probes for all persistent services. A single render scheduler and single analysis slot remain the supported topology. The production overlay binds HTTPS to loopback and mounts the operator’s TLS material read-only into unprivileged Nginx. Back up PostgreSQL and the media volume together while writers are stopped. Restore with the original Fernet key to fresh volumes and a fresh broker. See the tested procedure in README.md.

## Known limitations and next phase

The current deployment uses separate render and analysis workers, one embedded scheduler and local shared storage. The library shows the most recent 100 recordings and the latest 100 exports per source. Recording publication enforces the source budget. Retention, physical volume capacity and backup policy belong to the personal operator. Completed exports have a configurable aggregate quota. Production containers have been exercised with rootless Docker in a Linux VM, including sandboxed FFmpeg encoding. The personal studio has one owner per database, broker and media volume. An account for a second person would require a separate deployment or a new identity and ownership design.

The tiny model can miss speech mixed with game audio. Chunk boundaries can split phrases, the reaction vocabulary is English, and sparse sampling can miss short events. Review suggestions before export. The analysis image fetches pinned model weights during build and runs inference offline. No paid API or LLM is used. Subtitle timing is segment-level. Timing of individual pages within longer segments is approximate, and browser font metrics can differ from the burned export. The reviewed MP4 is the final visual reference. The remaining provider acceptance check is consent, revocation and clip entitlement on the operator’s own registered accounts. Cloud storage and multi-user identity remain future work.

## Direct HTTPS recording import

Implemented private asynchronous MP4 import alongside browser upload. The API validates the URL and DNS, queues a PostgreSQL job, and exposes recent jobs and cancellation. Celery Beat dispatches a dedicated outbound-capable import worker. A PostgreSQL advisory lock allows one active download across workers and admission allows four unfinished jobs. A completed import uses its generated job UUID as the ordinary Video UUID. Registration and completion commit together through the shared quota-checked publication service. Preview, clip rendering and analysis use the existing video routes.

The reusable URL service accepts public HTTPS on port 443, with signed query strings, and rejects credentials, fragments and provider watch pages. DNSPython bounds lookup time; every answer must pass public-address checks. Each request including each of at most three redirects resolves independently and connects a socket to a validated numeric IP. TLS verifies the original hostname. No proxy, cookies or authorization headers are forwarded. Download URLs are encrypted while queued with a domain-separated key derived from the deployment’s random broker credential and removed at claim/cancellation. Celery messages and status responses carry no URLs.

The worker streams 256 KiB blocks to private staging, checks actual bytes, rate, wall time, storage quota and free space, then invokes the existing restricted FFprobe and full FFmpeg decode on that local file. Defaults are 8 GiB per job, 14,400 seconds of media, 3,600 seconds for download, 1,800 seconds for decode validation, 8 MiB/s and 512 MiB disk reserve. Analysis scratch is capped at 768 MiB to accommodate long PCM audio. Existing AI worker deadlines still apply. Unknown-length downloads report bytes. Cancellation and worker recovery discard partial media. Interrupted downloads restart by explicit resubmission. Browser upload limits are independent.

The direct URL must return an accessible H.264 MP4 with optional AAC audio. Login pages, manifests, DRM media and provider watch-page extraction are outside this path. Monitor the importer alongside other writers and stop it for a consistent backup.

## Automatic clipping of recorded media

The original recorded workflow extracted speech, audio and visual observations and ranked short event windows, then required the operator to approve timestamps and submit a render. A reaction keyword could count alongside the presence of that same speech. The export engine already supported portrait crop and subtitles. The workspace now offers **Generate AI Clips** for a supported URL. Existing local recordings also have a secondary automatic option in the editor. Both manual workflows continue to use the existing services.

- Authenticated POST and GET at `/api/videos/{id}/auto-clips` create a durable generation request and return progress, warnings, source ranges, editorial score components and ordered export jobs. The analysis worker plans pending requests after ranking. It commits the job list and render jobs together. Deterministic job identifiers, unique insertion and the existing database locks let the operator return to the results or repeat a request. Individual failed exports use the existing retry route.
- The analysis worker processes recordings longer than five minutes in successive five-minute windows. It persists the next source offset and compact observations after each window. It decodes local mono 16 kHz PCM and transcribes active 30-second blocks with bundled CPU INT8 Faster-Whisper tiny, VAD and word alignment. OpenCV measures motion and histogram change on a 160 × 90 proxy at two frames per second. Timings are offset onto one source timeline before ranking, including observations on either side of a checkpoint. No external inference service is required.
- Ranking uses configurable intensity-change, scene, motion, speech and reaction weights. A candidate needs corroborating observations or a measured setup/reply exchange. The final points combine weighted signals (65%), hook (10%), context (8%), payoff (12%) and pacing (5%). These are deterministic editorial estimates. Per-candidate records include the measured event, source range, transcript evidence and score breakdown.
- The planner selects up to ten distinct edits in rank order, rejects overlapping source ranges and repeated dialogue, and looks for a preceding setup and the end of the response or ongoing visual activity. Scene-aligned boundaries must be near a proposed edit and outside speech. The preferred range defaults to 20–60 seconds and can be configured with `AUTO_TARGET_MIN_SECONDS` and `AUTO_TARGET_MAX_SECONDS`. A coherent event can fall outside the target. The source envelope is capped at 180 seconds. The saved edit includes chronological spans, aligned output cues, framing, optional zoom time and supporting observations.
- The existing FFmpeg render worker seeks the private local source, omits sustained pauses when both audio and visual evidence support a cut, concatenates at most four spans, offsets captions across joins and encodes one 720 × 1280 MP4. The fixed filter graph applies short audio fades at joins, single-pass loudness normalization and a peak limiter. Persistent localized motion can guide a crop within each measured scene, with center framing as fallback. Existing saved plans retain their compression preset. A short zoom can emphasize the measured event. Confidently aligned reaction words can receive a fixed ASS color. Legacy segment-only transcripts use phrase timing. Silence produces no captions. Restricted execution, output quotas, private previews, temporary cleanup and FFprobe validation are shared with manual rendering.
- Limitations include ASR errors in noisy or overlapping speech, block boundaries that can split utterances, English setup/reaction vocabulary, and motion-based framing that may miss the intended subject. Sarcasm, speaker identity and game outcomes are not directly recognized. Static dialogue can be missed. Duration and result count depend on the evidence. Checkpoint files bound per-window media decoding, while persisted observation counts grow with recording duration. Multi-hour editorial quality and sustained performance still require evaluation on representative authorized recordings.

## Server-side recording source resolution

The workspace submits one URL to the authenticated imports endpoint, with automatic generation enabled. The earlier frontend routed playback URLs to the saved-recording endpoint and handled its missing-source response by requiring a local selection or upload. The workspace now leaves source resolution to the server. Manual uploads and previously linked private recordings remain accessible.

- The adapters in `app/services/recording_sources.py` normalize direct HTTPS MP4s and official Twitch clip downloads into a validated transfer URL and a stable submission identity. Only the private importer receives the encrypted transfer URL. Original source bytes are staged in bounded blocks, quota-checked, probed, fully decode-validated, and published atomically. The same transaction queues automatic analysis. Neither a page URL nor a provider access token is sent to FFmpeg.
- Twitch clip links use the connected broadcaster’s Helix clip-download entitlement and require a matching clip ID and a validated CDN URL. A Twitch VOD page supplies playback/metadata; native clip creation is a separate operator action. [Twitch Clips API](https://dev.twitch.tv/docs/api/reference/clips)
- YouTube watch, share, live, shorts and embed links identify playback resources. The existing OAuth grant lists the connected channel and its broadcasts. The Data API returns video resource fields, including some owner-only metadata. It supplies no general video-file download through this integration. The developer policies restrict copying audiovisual content. [YouTube Data API](https://developers.google.com/youtube/data/reference/rest/v3/videos/list) · [Developer policies](https://developers.google.com/youtube/terms/developer-policies)

## Automatic engine evaluation and completion

The complete automatic route reuses the source adapters, importer, checkpointed analysis, edit planner and render jobs above. It requires no manual timestamps after a supported URL submission. Ingestion security and provider access limitations remain unchanged; YouTube watch pages are not downloadable media sources. There are no new runtime dependencies, paid APIs, or LLM adapters. Actual inference uses local Faster-Whisper tiny CPU INT8, NumPy and OpenCV.

Candidates now retain timestamped transcript context as well as measured signal evidence and the existing deterministic hook/context/payoff/pacing score components. Automatic generation rescoring also expands older manual analyses to the 60-candidate pool without repeating inference. The planner walks backward through connected utterances to retain a setup before its payoff, while enforcing the configured context envelope, overlap suppression and ten-output ceiling. Results include a short description drawn from observed dialogue and label scores as estimated engagement. Counts remain evidence-dependent; no filler is added to meet five outputs.

The saved EDL contains source spans, clip-relative caption pages and emphasis, optional event zoom, audio preset and scene-relative framing intervals. The separate plan validator checks ordered spans, duration consistency, caption bounds, complete crop coverage, crop positions, frame rate and fixed audio presets before FFmpeg argument construction. Scene framing switches only at measured scene cuts or retained-span joins, using stable localized motion or center fallback. It is not face or speaker tracking. New automatic exports use bounded single-pass loudnorm targeting -16 LUFS / -1.5 dB true peak, 48 kHz resampling with regenerated audio timestamps and a final limiter. This avoids the nonmonotonic DTS discovered during real rendering. Manual export and previously saved plans remain compatible.
